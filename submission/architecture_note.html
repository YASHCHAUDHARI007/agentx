ShelfSense: architecture note

AgentX Challenge 1, Anticipatory Commerce · finds the product before the shopper finishes the sentence · github.com/YASHCHAUDHARI007/shelfsense

Why it does not commit wrong

Key invariant. Once exactly one product fits everything said, a new constraint can only confirm it; only a correction can change it. So the per-word decision is not "how confident am I in this product?" but "could a correction still come?". A wrong commit costs 1.0, more than the best possible gain from a request, so the policy only commits when that risk is near zero.

  • Commit at once if a correction already happened (dev requests correct themselves at most once), or a budget number made the match unique mid-sentence (150 of 150 right).
  • Otherwise wait one word that is filler or an unpunctuated value. Words ending in "." or "," never count: corrections open a new clause ("size 8, | I mean 7").
  • Never while a correction cue awaits its value ("no, change that to"), the prefix ends mid-thought ("under", "one thousand"), or a word was unknown or only guessed.
  • Speech-aware (auto, default). Raw speech-to-text has no punctuation, so a correction can follow a complete request directly. Until a request shows punctuation, only filler counts and nothing commits at once. On speech-style input this cut wrong commits from 19 to 1, for 0.4 points on punctuated dev.

Parser

Re-parses the whole prefix every word (microseconds), so corrections need no special state: the last mention of a slot wins. Longest-phrase match over the profile's phrase table; numbers ≥100 are budgets, real sizes are sizes; word numbers stay open while they can still grow ("two thousand … five hundred"). Repairs typos (Damerau-Levenshtein, one reading only), glued sizes ("UK9"), "-ish" colours and Hinglish numbers ("do hazaar", "dhai hazaar tak").

Any catalogue

catalogue.py detects the id, price, title and filter columns and their roles from a shop's CSV, and builds every phrase for every value: English/Hinglish packs, automatic variants ("128GB"/"128 gigs", "t-shirt"/"tshirt", plurals), and the shop's own synonyms. Each shop gets its own Vocab, so one process serves many shops.

How we tested

  • Stress set: generated dev-format requests with wording the parser was not written for ("nevy", "UK9", "smol", new correction phrases).
  • Holdout: separate phrases and seed; used once to find two safety fixes, so slightly optimistic.
  • Speech-style: sets re-run with punctuation stripped. The electronics shop (different columns, unit values) exposed the punctuation risk that led to auto.
  • Every wrong commit read by hand; fixes kept only if no set got worse.

Latency, cost, scale

  • 0.03 ms per word (p95 0.15 ms); 0.37 ms CPU per request including search; about 2,700 requests/s per core. No language-model calls at run time.
  • 1.04 searches per request: one fetch of category + colour, then local narrowing. Re-reading a revised speech transcript reuses cached searches.
  • Service: Python standard library HTTP API, with sessions, /words and /transcript (interim words held until they settle, revised words re-read), API keys, rate limits, Prometheus /metrics, an OpenAPI contract, a decision log, a Docker image, and 49 automated tests in CI with a score gate.
  • Front end: Next.js (React, TypeScript), exported to static files and served by the same Python process, so production needs no Node.js.

Rezolve Labs capabilities used

  • Managed knowledge retrieval: the catalogue CSV is uploaded once as a knowledge-base document (tools/rezolve_setup.py).
  • Semantic product search (/product-discovery/search, with filters and price_lte): the fallback in finish() when the parser cannot pin one product (unknown product words, guessed categories). It is sent only the filters the agent is sure of, prefers results that agree with the local reading, and every call is counted as a search. Clean requests never call it: 0 of 300 dev requests.
  • Status: client, setup and fallback are built and tested with a local stand-in; live calls need the team's Rezolve Labs API key. Without a key, or on any API error, the agent runs offline unchanged.
  • Next: Rezolve live transcription for the voice demo, and semantic search as the main retrieval for catalogues too large to narrow locally.
